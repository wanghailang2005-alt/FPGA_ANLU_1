# 真实视频时序链的 OSD 验证

日期：2026-10-20。用户上板反馈：图片正常，HELLO FPGA 未显示；用户确认选择的是 OSD 候选 bit。此反馈仍为待解决问题，不能用本仿真替代板测结果。

本次按用户“开始”的批准，仅新增测试平台、运行入口与证据，没有修改候选或原工程 RTL、PLL、SDC、按键、IP，也没有重新生成 bit。

## 实际测试链

直接编译候选中的 `color_bar`、`video_timing_data`、`video_delay`、五个 OSD 模块和 RGB-to-AXIS。测试使用与实际候选顶层一致的 `top_osd_insert.vh`；已以文本比对确认片段存在于候选顶层，五个候选 OSD 文件与仓库 RTL 字节相同。

链路为：真实 color_bar → video_timing_data → video_delay → 实际 OSD 接入片段 → 实际候选 AXIS 适配器。25 MHz，640×480 有效区，800×525 总时序。原模块原样编译，不重新手写 HS/VS/DE。

SDRAM 的 read_data 以常量深蓝色 0x183048 代替，读帧请求在测试中立即响应；display_valid 在首帧第 10,000 个输出像素之后置高。它验证视频时序和字幕链路，未模拟 TF/SDRAM 的真实初始化、CDC、存储错误、加密 HDMI 核、PHY 或显示器。

独立参考坐标依据观察到的 DE 像素数、行边沿与 VS 下降沿计数，不读取 DUT 坐标计数器。参考字形使用独立位图固定值，逐拍检查 AXIS data/valid/USER/LAST；同时检查每行长度、帧高度及获取同步后的坐标有效性。所有视频输入在采样后经过五个寄存边界到达 AXIS，期望队列按这一延迟检查。

## 结果

ModelSim SE-64 2020.4：正常运行退出码 0，Errors 0 / Warnings 0。

| 检查 | 结果 |
|---|---:|
| 逐拍检查 | 1,679,202 |
| 有效像素 | 1,228,800（4×640×480） |
| LAST | 1,920（4×480） |
| SOF | 4 |
| 获取同步后的 frame_tick | 3 |
| 有效坐标像素 | 921,600（后三帧） |
| 输出文字白色像素总数 | 1,302（后三帧各 434） |
| 导出第三帧 | 307,200 像素，434 个白色文字像素 |

实际源复位后 VS 初值为低，第一次低→高尚不足以满足坐标模块约定的“非有效→有效→非有效”获取条件，因此首帧没有有效坐标和文字。第二帧前取得同步，文字启用；其后每帧正常。这是已知的一帧启动行为，不能解释持续没有文字。首版新测试误要求第一帧就有坐标，在 1.415701 ms 停止；检查启动约定后调整为首帧允许获取、后三帧必须有效，未修改 DUT 或绕过后续逐像素检查。

负向控制以 `+NO_OSD` 强制字幕使能为零，预期在第二帧第一个文字前景像素失败：t=18,728,541 ns，期望白色、实际深蓝；退出码 1。这确认自检能识别“图片正常但字幕始终关闭”，而非只验证像素数量。正常测试随后重新运行并导出完整画面。

输出 PNG 来自 DUT 的 AXIS 像素 PPM，经过无缩放格式转换并实际查看，确认左上角显示 HELLO FPGA。PNG 见 [真实时序仿真画面](real_timing_osd.png)，日志见 [正常日志](modelsim_real_video_timing.log) / [负向日志](modelsim_real_video_negative.log)。完整 PPM 可重跑生成，不提交约 3 MB 的中间文件。源文件哈希与计数见 [机器可读摘要](real_timing_summary.json)。

```powershell
& 'E:\Modelsim\win64\vsim.exe' -c -do run_real_video_timing.do
```

```powershell
& 'E:\Modelsim\win64\vsim.exe' -c -do 'set negative_test 1; set log_file ../evidence/modelsim_real_video_negative.log; do run_real_video_timing.do'
```

预期退出 1；负向运行不会覆盖正常预览 PPM。

## 结论与下一步边界

真实时序下，现有 RTL 能产生正确字幕，SIM PASS；板上不显示的根因仍未找到。不能据此认定用户看漏、下载有误或直接归因于已有 SDRAM 负裕量，也不能认定综合实现后的逻辑与 RTL 一定一致。现有全局时序 FAIL 不因本次仿真改变。

建议后续另行批准带可见诊断标记的独立实验候选：显示一个固定版本标记，并显示经过同等延迟对齐的字幕使能/坐标有效状态，以区分板上使能未开、坐标未获得与字体/实现路径问题。需提交具体 RTL/接口、延迟和验证范围后再实施，本次未添加诊断标记、未改 bit。
