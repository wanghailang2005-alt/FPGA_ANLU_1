# 仓库结构与维护约定

[返回首页](../README.md) · [文档目录](README.md)

## 内容放置

| 位置 | 作用 | 查找方式 |
|---|---|---|
| README.md | 项目介绍、当前交付与主要入口 | 初次访问从这里开始 |
| integration/README.md | 按版本和阶段整理的索引 | 查最新版本或历史回退 |
| integration/版本目录/ | 该版本源码、测试、报告、反馈与清单 | 使用同一版本的配套文件 |
| rtl/ | 早期可独立使用的 OSD 模块 | 不代表当前整机源码全集 |
| sim/ | 早期 OSD 测试及依赖原工程的测试 | 先读本目录 README |
| docs/ | 使用、结构、专题和研发记录 | 当前入口见 docs/README.md |
| docs/history/ | 旧首页、旧操作规划等历史文档 | 仅用于追溯当时状态 |
| evidence/ | 早期诊断及验证材料 | 后续版本证据保存在各自 integration 包 |
| tools/ | 文档链接检查 | 在仓库根运行 node tools/verify_document_links.mjs |

## 后续维护

1. 最新交付统一由根 README 和 integration/README.md 指向；更新版本时同步这两个入口。
2. 每个集成归档保留自己的源码、测试、依赖和验证说明。已有归档路径、清单、历史日志保留，以便复核。
3. 文档说明应区分用户板测反馈、设备端哈希核对、仿真及实现时序。新版本状态不覆盖旧日志的原始结论。
4. 厂商加密 IP、完整 TD 工程、数据库、bit 与媒体素材沿用本地保存范围。上传文件前检查第三方来源与许可。
5. 修改文档后，提交前运行已有链接检查工具；它检查当前变更和新增 Markdown 的相对文件链接，不校验网页可达性或 Markdown 锚点。
