# 缓存仲裁局部修复 1

> 本记录中的未带链接的相对路径以 `zoom_animation` 工程根目录为准。

2026-10-29。用户板测结果为 A（缓存旁路）静态干净、无动画，B（缓存开启）静态有噪点、动画存在。用户选择“先做 1”，在现有 zoom_animation 内进行局部仲裁修复，保留时钟、插值、动画结构和已有 A/B bit。

## 上板顺序

1. 下载 `ZOOM_CACHE_ARB_FIX1_20261029.bit`，按 K1，SW4..SW1=`0000`。
2. 用 K2 选择与 A/B 测试相同的草莓，先观察原尺寸静态画面和黑边 5 秒，暂不启动动画。
3. 如果静态仍有噪点，SW=`1111`，不按键，拍约 5 秒数码管视频，反馈“修复1静态仍有噪点”。本轮暂不改频率或启动其他修复方案。
4. 如果静态干净，再拨 `1000` 按 K3，观察逐步放大；等待完成后再循环。草莓为 4:3，等比例留边和铺满的目标相同，第二次没有尺寸变化属于正常，第三次应逐步缩回。
5. 再测试竖图／不同尺寸、K2 切图、K4 轮播以及原 OSD／字幕／转场／音频。

本版仍是待板测候选，不能凭仿真或时序报告声称噪点已消失。更保守的存储访问可能延长大尺寸图片的装载和动画时长，优先验证稳定性。拨码与按键职责沿用动画版；原诊断 F 页保留。

## 实际修改

仅修改两个已有 RTL 文件：

- `SD/frame_read_write.v`：增加实际未返回读请求计数。原读 DMA 的固定十拍尾部等待保留，但交接不再只依赖它；未排空或控制器 busy／刷新期间不启动新的读／写 burst，也不交给缓存。异常返回／计数溢出时停止启动新事务，复位后清除。
- `SD/zoom_source_cache.v`：默认辅助事务由最多 32 字降为 8 字；上传等够 8 字再发，最后不足 8 字按尾包处理，避免慢速像素到达触发大量单字争用。读包在 256 字列边界拆分。取得访问权前需要 8 个连续空闲周期；发送短包时不把自身 busy 误作逐字 ready，但刷新期间仍暂停命令且保持访问权。读结果实数排空、控制器空闲且保持 16 个安静周期后再释放，并让出至少 64 个内存周期。

DDR/SDRAM 厂商 IP、PLL、100/125/25MHz 时钟、ADC/SDC、原静态缩放算式、双线性流水线、动画 DDA／帧调度、RGB/DE/HS/VS 延迟均不改。缓存行数据接口仍为 valid/ready，busy 和行 fetch 等待可以变长；载荷与 valid 的拍数不变。观察探针也保持字节一致。
