## 下载哪个文件

候选目录内生成两个独立命名 bit，实际 SHA256、构建源码哈希、资源与时序以 `evidence/stall_diagnostic_builds.json` 及对应报告为准：

1. `OSD_DIAG_DYNAMIC_20261025.bit`：先用它复现，屏幕仍显示 IMG/AUTO。
2. `OSD_DIAG_FIXED_LEGACY_20261025.bit`：用同一 TF 卡、同一组图片重复操作，屏幕显示 HELLO FPGA，读缓冲区选择恢复旧接线。

第二个版本同时改变文字模式和读选路，是对“动态接入整体”的对照，不能单凭结果断言是字形排版或邮箱某一处出错。重新综合/布局也会改变物理实现；若两版均有时序违例，更不能把单次对照当成因果证明。

当前工程源码最终留在 OSD_STATUS_MODE=1。命名 bit 与构建清单一一对应，不要把旧的 OSD_STATUS_IMG_AUTO bit 当作本诊断版。

## 卡住后看什么

原来显示 1 的状态位可能变成：

| 状态 | 含义 |
|---|---|
| 6 | 源读取完成，计数达到 307200，加载尚未提交，重点检查写完成确认 |
| 7 | 源读取完成，但计数不等于 307200，重点检查有效像素数量 |
| 9 | 加载仍忙，但 BMP 读取器已空闲，且尚未记录源完成 |
| 8 | 原有 BMP 读取错误诊断，维持原来的错误分页 |
| 1 | BMP 读取器空闲；若仍停在 1，需要进一步检查是不是 load_busy 其实已清零，不能套用上述等待结论 |

对于 6/7/9，其余五位会显示像素计数；连续无进展两秒后，计数和冻结标志每秒交替显示。请拍 **至少 4 秒录像**，尽量拍到完整六位数码管和屏幕，不要先按复位。

### 像素页

五位十六进制。完整 640×480 对应十进制 307200，即 `4B000`。

计数沿用原有上限饱和，达到 307200 后不再增加，不能用它检测超量像素。数码管 0～F 使用原工程字形，B/D 可能显示为小写 b/d。

### F 开头的标志页

格式 `F a b c d`，每个位置是一位十六进制数，四个 bit 按下面顺序排列，高位在前：

| 字段 | bit3 → bit0 |
|---|---|
| a | load_busy、source_done_seen、write_done_seen、write_finish_pulse |
| b | bmp_ready、write_req、write_req_ack、sd_init_done |
| c | load_idx[1:0]、disp_buf_idx[1:0] |
| d | wrfin_tgl_sync[2]、wrfin_tgl_sync[1]、next_req_pending、auto_play_en |

例如 a=C（二进制 1100）表示加载忙、已见源完成、尚未见写完成。c 的高两位加一才是目标图片号；低两位只是缓冲区编号。write_done_seen 是 SD 域实际收到的写完成记录，不等于直接观测 SDRAM 内部已经完成。脉冲在快照时通常为 0，不能因此断言它从未发生。

标志页一旦冻结就不随 K4 变化；屏幕 AUTO 是当前状态，两者用途不同。请先录像，再测试 K4，最后用 K1 恢复。

## 对照步骤

1. 同一张卡放相同图片，最好图片本身标有 1～4；不要在两版之间重拷或重排文件。
2. 先下载动态诊断版，分别进行慢速 K2 切图与自动轮播，记录停在哪张、操作次数和完整数码管读数。
3. 发生停住先拍 4 秒录像，记录 K4 是否仍改变 AUTO，随后 K1 复位。
4. 下载固定/旧选路诊断版，保持接线、卡和操作节奏，重复同样次数。
5. 返回两版结果。固定版一次未复现不能证明故障消失；需多轮重复。
