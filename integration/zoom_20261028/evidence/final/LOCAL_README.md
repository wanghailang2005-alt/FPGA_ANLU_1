## 改动边界

- 唯一功能RTL变化是`SD/scale_on_load.v`的BLACK状态新增准备拍；进入黑边行时清零准备状态，输出成功后重新等待一拍；FIFO暂停时保持就绪，不推进坐标。
- 所有源像素选择、RGB颜色、黑边位置、模式、整帧307200像素、源尾部排空和提交条件不变。
- 源码目录与zoom_fix逐文件哈希比较，除上述核心外必须一致。诊断页、数码管、OSD、字幕、HDMI、SDRAM、厂商/加密IP、PLL及SDC/ADC沿用。
- 黑边生成耗时增加；新增的准备拍只发生在写帧过程，不增加显示端RGB/DE/HS/VS延迟。原版正常每拍黑像素改为每两拍最多一个；图片区域仍每两拍最多一个。
- 重新实现会改变物理布局布线，因此即使板测改善也不能单凭一次对照断言原故障的全部根因。

## 本次上板只看这些

1. TF卡使用当前已验证能读取的水果/爱心素材，不再改卡。下载本目录命名bit，按K1复位，SW4..SW1=`0000`。
2. 按K2找到320×240草莓，等待装载结束。不要先按K3，观察原尺寸居中画面上下及左右是否纯黑，原密集横线是否消失。
3. 若仍有横线，切SW=`1111`和`1110`记录数码管，再拍照；这两页不重载图片。
4. 若黑边正常，再用SW=`0111`按K3循环三模式，核对居中/留边/铺满效果和切图。640×480源图三模式相同属正常。
5. OSD和字幕字形为黑色；它们落在纯黑边内时不可见属配色结果。切到图片白背景或1010灰帧再确认文字，不能把黑字黑底当作字形故障。
