# 每张图片对应的中英文字幕（跟随切图 + 中文滚动）

版本：V1.5  
日期：2026-11-03  
基线：`zoom_animation_8transitions.zip`（V1.4）  
改动文件：`osd_overlay.v`（字幕数据由脚本生成）  
新增：`tools/gen_captions.py`（字模与字幕表生成脚本，不参与综合）  
未改动：转场、亮度对比度、缩放、读卡、SDRAM、PLL、约束、`.al` 工程清单

## 1. 效果

- **中文**：16x16 点阵，第 400~415 行，**跑马灯横向滚动**，内容随当前显示的图片切换；
- **英文**：8x16 字形，第 424~439 行，**居中静态**，内容同样随图片切换；
- 换图时中文字幕**重新从右侧进场**，不会接在半句上；
- 滚动速度/方向沿用 `SW=0010` / `SW=0011`（和底部滚动条共用一套设置）；
- `SW=1100` 仍然控制字幕层开关：关闭 / 只中文 / 只英文 / 双语。

## 2. 怎么做的

字模与字幕表不是手写的，是脚本从字幕文本里提取生成的：

```text
python tools/gen_captions.py
```

脚本做三件事：

1. 从 `场景一_滚动字幕.txt` 里解析出 4 条正文（每个「01 xxx：」标题后面的那一行）；
2. 用 16px 宋体渲染成 16x16 点阵，去重后得到 **93 个不同字形**；
3. 把「字幕序号→起点/长度」「字格序号→字形序号」「字形→16 位点阵」「英文标题」四张表
   直接写进 `osd_overlay.v` 的生成区（`// ==== 以下由 tools/gen_captions.py 自动生成 ====`）。

本次数据量：**4 条字幕、126 个字格、93 个字形**。

**换场景二（森林步道）**：把脚本里的 `SUB` 路径改成 `场景二_森林步道\02_字幕\场景二_滚动字幕.txt`，
同时改 `EN_TITLES` 四行英文，重新跑一次脚本，再综合即可。注意场景二有 5 张图，
而板子只扫描前 4 张，所以第 5 条（森林防火海报）的字幕用不上。

## 3. 排布

```
y=400..415   中文（16x16，跑马灯，速度 1/2/4 像素每帧）
y=424..439   英文（8x16，32 字符窗口居中）
y=448..463   底部滚动条（原有，与字幕互不影响）
```

中文每帧走 1/2/4 像素，一条 40 字的字幕（640 像素宽）走完全程约 1280 像素：
慢档约 21 秒、快档约 5 秒一圈。

## 4. 资源提醒（重要）

93 个字形 × 256 位 ≈ 2.4 万位点阵，综合成 LUT 大约 **2000~4000 个 LUT**。
原工程 LUT 约 55%（10754/19600），加上后预计 **70~75%**。

请在 TD 里重点看三件事：

1. `#lut` 是否超过 85%；
2. 综合是否有 "cannot fit" / 布局拥塞告警；
3. `video_clk`（25 MHz）的 setup 裕量。

**如果放不下或时序不好**，两个降级办法（都不用改代码结构）：

- 用脚本把字幕截短（脚本里 `caps = caps[:4]` 之后加一行 `caps = [c[:16] for c in caps]`），
  字形数会从 93 降到 60 左右；
- 或者只保留 2 条字幕（`caps = caps[:2]`）。

## 5. 板上验证

1. TD 重新综合实现、下载（本包不含 bitstream）。
2. 拨 `SW=1100` 到双语，按 K2 逐张切图，中文应跟着换成对应那条、并从右侧重新进场。
3. `SW=0010` 切速度、`SW=0011` 切方向，中文和底部滚动条应一起变。
4. 观察中文笔画是否完整、有无上下偏移（16px 宋体在 480 行画面上偏细，远看可能发虚）。
   若觉得太细，用 `tools/gen_captions.py` 里把 `FONT` 换成 `simhei.ttf`（黑体）重新生成。
