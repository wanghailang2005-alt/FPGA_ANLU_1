## 测试步骤

1. 下载本诊断 bit，按 K1，SW=0000，K2 找到 241×360（OE）图，等静态图完成，确认静态情况。
2. SW=1000，按一次 K3，等待动画结束，观察是否出现噪点。不要切图或复位，以免清除校验状态。
3. SW=1111，不按 K3。数码管每秒轮换四页 F、1、2、3，录制至少 6 秒视频，并拍显示器画面。无需手动倒读，扫描方向可能使显示顺序反过来。
4. 再按 K1，用同样方法测试 240×360（EE）作对照。每次只做一次放大；完整动画结束后再看 1111。

3 页的逻辑格式为 `3sssss`，五位十六进制值中，bit19 表示已完成至少一行比较，bit18 表示至少一行不一致，bit17:8 是首次不一致的源行号（缓存底向上编号，0 开始），bit7:0 是已比较行数，饱和于 FF。常见 `3800FF` 表示检查过且未发现不一致；`300000` 表示还没有完成行比较，不可当作通过。发生不一致时最高数据位为 C 至 F，具体值视行号而定。换图/重置清除状态；为避免错过，出现噪点后先拍数码管再换图。F 页原状态保留。

## 校验范围和局限

在 125MHz 存储时钟域，对每一行实际发给 SDRAM 的 32 位缓存写入数据做旋转异或签名，保存至片上行签名 RAM。动画缓存读请求完成相同行的全部返回数据时，以同一算法比较。出现不一致时锁存首个行号；比较过程只观察现有写命令和读返回，不改变原数据或握手。每次换图通过现有上传请求清除状态；最多支持现有 1024 行。跨时钟显示使用已有握手邮箱。

签名不是逐像素比较，多个差错可能相互抵消；未报错不能证明每个数据都正确，也无法覆盖缓存写命令之前或读返回之后的错误。报错说明写命令与对应读返回的签名不同，但不能单凭它区分写、存储、读路径或采样时序，也不能直接声称某处为根因。

故障注入仿真：干净行不报错，单个位错误能检出并锁存行 2，后续保持，换图清除；奇偶行宽均覆盖。缓存最大尺寸回归通过；241×360 完整一次 24 步动画、生成和视频逐像素比对通过，校验器不误报。原 SDRAM 物理模型为空壳，仿真不能验证真实存储数据。约束内实现 setup +0.133ns、hold +0.019ns，STA 覆盖率 95.01%；原相关 SDRAM 时钟时序例外仍存在，不代表完整接口时序闭合。真实板测待确认。
