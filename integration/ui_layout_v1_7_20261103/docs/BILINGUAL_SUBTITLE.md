## 1. SW=1100 的四种模式

| 模式 | K3 顺序 | 画面 |
|---|---|---|
| 0 | 第 1 档 | 字幕关闭 |
| 1 | 第 2 档 | 只显示中文 |
| 2 | 第 3 档 | 只显示英文 |
| 3 | 第 4 档 | 中英双语上下叠加（默认） |

- 按 K3 循环：关闭 → 中文 → 英文 → 双语 → 关闭；
- 默认上电为双语，要默认关闭把 `user_control.v` 里 `SUB_MODE_RESET` 改成 `2'd0`；
- 状态栏第三行同步显示 `SW:1100 V=n`。

## 2. 画面布局

```
y= 16.. 31   IMG:n
```

- 字幕层与 `0001` 的文字显示模式**互相独立**：即使 `0001` 设成"关闭"，字幕层照常显示；
- 与滚动字幕、亮度/对比度提示不在同一行区，互不覆盖。

## 3. 中文支持是怎么做的

原来只有 8x8 ASCII 字库，没有中文字模。这次在 `osd_overlay.v` 里增加了：

- **16x16 点阵字模**：12 个汉字，每个 32 字节，用 `256'h...` 常量按行存放，
  由 `zh_bitmap_row(字形号, 行号)` 查表；字形号到字格的映射由 `zh_slot_of()` 给出；
- **独立的两级流水**：中文字形位宽 16 位，无法复用 8 位的 ASCII 字形通路，
  所以单独做了一级取行、一级取点，整体延迟与 ASCII 通路相同（2 拍），
  两者在输出级用"或"合并成黑色文字；
- 字模来源：16px 宋体点阵（二值化阈值 110），脚本 `tools/gen_zh_font.py` 可复现。

**换字幕文字**（例如换成别的景点介绍）：

```text
python tools/gen_zh_font.py "你的中文短句"
python tools/gen_zh_font.py --font C:/Windows/Fonts/simhei.ttf "你的中文短句"
```

脚本会打印两段 case，分别替换 `osd_overlay.v` 里 `zh_bitmap_row` 的 case 内容和
`zh_slot_of` 的 case 内容即可。约束：

- 最多 16 个字格（含空格），对应 256 像素宽；
- 不同汉字的个数不超过 12 个（`BLANK_INDEX` = 12，第 12 号留给空白字模）；
- 想放更长的句子，需要把 `ZH_LEN` 调大并同步改 `zh_slot_of`（字格数上限 16 是由
  `zh_local[8:4]` 的 4 位索引决定的，要更多就得加宽索引）。

英文那行是固定文本，改 `sub_en_glyph()` 的 case 即可（每个字符 8 像素，40 字符正好 320 像素，
超过 40 个字符要同步调 `EN_LEN` 和起始 x）。

## 4. 诊断页让位

`SW=1100` 原来是诊断页编码，现在改为字幕语言选择：

- `diagnostic_page` 改为 `SW==1001 || SW>=1101`；
- 拨 1100 时数码管恢复显示正常状态（状态机 + 像素计数）。

## 5. 资源与时序

- 中文查表：12 个 256 位常量 + 一个 16 选 1 的 16 位选择器，估算几百个 LUT；
- 英文那行复用原有字形通路，只多了一个 40 项的字符查表；
- 全部在 `video_clk`（25 MHz）域，组合路径只有一级查表 + 一级选择，时序压力很小；
- 具体资源以 TD 报告为准（原工程 LUT 约 55%、DSP 22/29）。

## 6. 板上验证步骤

1. TD 重新综合实现、下载（本包不含 bitstream）。
2. 拨 SW=`1100`，状态栏显示 `SW:1100 V=4`，底部应有中文 + 英文两行字幕。
3. 每按一次 K3：双语 → 关闭 → 中文 → 英文 → 双语，观察两行字幕的显示/隐藏。
4. 检查中文笔画是否完整、有无上下偏移；如某个字辨识度差，用脚本换字体（`--font`）重新生成。
5. 切换 `0001` 文字模式，确认字幕层不受影响；切换 `1010/1011`，确认亮度/对比度提示与字幕互不覆盖。
6. 按 K1 复位，字幕回到默认双语。
